# Desktop-facing API

The VC Composer desktop app talks to this site through four endpoints. The
shapes below are what the code in `src/app/api/` does today, and they match VC
Writer's endpoints of the same names, so a client written against either
works against both (the only additions are the optional `channel` query
parameter on the two release endpoints).

All responses are JSON. Errors always carry `{ "error": string }` (plus extra
fields where noted).

## Authentication

Endpoints marked **Bearer** take the signed-in user's Supabase access token:

```
Authorization: Bearer <supabase access_token>
```

The app obtains the token by signing the user in against the Supabase project
(`NEXT_PUBLIC_SUPABASE_URL` with the anon key, email + password or emailed
link) and refreshes it as Supabase tokens expire. The same endpoints also accept
the website's session cookie, which is how the account page calls them.

## POST /api/licenses/activate

**Bearer.** Activates this installation against a licence on the signed-in
account. Rate limited: 30 requests per hour per client address.

### Request body

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `serial` | string | no | max 60 chars; case-insensitive. If omitted, every licence on the account is tried, live ones first. |
| `deviceFingerprint` | string | yes | 8 to 200 chars; stable per install, generated by the app |
| `deviceName` | string | no | max 120 chars; default `""`; shown to the user on the account page |
| `platform` | `"windows"` \| `"macos"` | yes | |
| `appVersion` | string | no | max 40 chars; default `""` |

A serial is never enough on its own: only licences owned by the authenticated
account are considered, so a leaked serial cannot use somebody else's seats.

### 200: activated

```json
{
  "activated": true,
  "reason": "new_device",
  "license": { "serial": "VCC-ABCDE-FGHJK-LMNPQ-RSTUV", "maxActivations": 2 }
}
```

- `reason`: `"new_device"` (took a free seat), `"already_active"` (this
  fingerprint already holds a seat; reinstalling never uses a second one), or
  `"reactivated"` (this fingerprint held a seat before, was freed, and reclaimed it).
- `license.maxActivations`: number of computers the licence covers, or `null`
  for a master licence (any number).

Activation also stamps `last_seen_at` and the app version on the device record.

### 409: refused

```json
{ "error": "This licence is on 2 of 2 computers. Free a seat from My account and try again.",
  "outcome": { "result": "refused", "reason": "no_slots", "inUse": 2, "limit": 2 } }
```

```json
{ "error": "This licence is no longer active. If that is unexpected, check your account.",
  "outcome": { "result": "refused", "reason": "license_inactive" } }
```

- `outcome.reason`: `"no_slots"` (with `inUse` and `limit`) or `"license_inactive"`.
- `license_inactive` is also returned when the account has no licence at all
  (`error` then says so, or "That license is not on this account." when a
  `serial` was given that the account does not own), when every licence has
  lapsed (expired subscription, revoked, suspended), and, rarely, when the
  activation could not be written ("The activation could not be recorded. Try
  again in a moment.").
- `error` is a sentence suitable for showing to the user.

### Other responses

| Status | Body | When |
| --- | --- | --- |
| 400 | `{ "error": "A device is required" }` | body missing or fails the rules above |
| 401 | `{ "error": "Sign in to activate VC Composer" }` | no or invalid token |
| 429 | `{ "error": "Too many requests from this address. Try again shortly." }` + `Retry-After` header | rate limited |

## GET /api/licenses/standing

**Bearer.** The account's licence standing, for the app to record with the date
it heard it. Reads only the caller's own rows, under row level security.

### 200

```json
{ "standing": { "status": "active", "expiresAt": "2026-12-16T09:30:00.000Z" } }
```

```json
{ "standing": { "status": "active", "expiresAt": null, "grant": "master" } }
```

```json
{ "standing": null }
```

- `standing` is `null` when the account has no licence at all. That is **not**
  a lapse.
- Otherwise it describes the account's liveliest licence: a live licence that
  never ends wins over one with a date; among live ones the later end wins;
  if none is live, the one that ended last.
- `status`: `"active"` | `"suspended"` | `"revoked"` | `"expired"`.
- `expiresAt`: ISO 8601 timestamp the subscription is paid up to, or `null`
  for a licence that never ends.
- `grant`: present **only** for a given licence, `"academic"` or `"master"`.
  Absent means bought (a subscription).
- A licence is live when `status === "active"` and (`expiresAt` is null or in
  the future). **Read the date as well as the status**: a lost cancellation
  webhook can leave `status` saying `active` after the period ran out.

How the app should act on this (grace period, read-only, staleness) is
`writingStanding` in `src/domain/subscription.ts`, pinned by its tests:
editable for `WRITING_GRACE_DAYS = 7` after the app first sees a lapse,
read-only after that, and an answer older than `STANDING_GOOD_FOR_DAYS = 30`
is never grounds for read-only.

| Status | Body | When |
| --- | --- | --- |
| 401 | `{ "error": "Sign in to check your licence" }` | no or invalid token |
| 502 | `{ "error": "The licence could not be read" }` | database error |

## GET /api/releases

**No authentication.** Version information for the updater; never a download URL.

### Query

| Parameter | Values | Default |
| --- | --- | --- |
| `channel` | `stable` \| `preview` | `stable` |

### 200

```json
{
  "builds": [
    {
      "platform": "windows",
      "version": "2.0.1",
      "minimumOsVersion": "10.0.17763",
      "releaseNotes": "What changed",
      "publishedAt": "2026-11-20T10:00:00.000Z",
      "sha256": "e3b0c442…"
    }
  ]
}
```

At most one build per platform: the active one on that channel. A platform
with nothing live is simply absent. `minimumOsVersion`, `releaseNotes` and
`sha256` may be empty strings; `publishedAt` may be null.

| Status | Body | When |
| --- | --- | --- |
| 400 | `{ "error": "Unknown channel. Use \"stable\" or \"preview\"." }` | any other `channel` |
| 500 | `{ "error": "Could not read the release catalogue" }` | database error |

## GET /api/downloads/{platform}

**Bearer** (or cookie). Mints a short-lived signed URL for the installer.
`{platform}` is `windows` or `macos`.

### Query

| Parameter | Values | Default |
| --- | --- | --- |
| `channel` | `stable` \| `preview` | `stable` |

- `stable` requires a live licence on the account covering the platform.
- `preview` requires only a signed-in account: no licence needed.

### 200

```json
{
  "url": "https://<project>.supabase.co/storage/v1/object/sign/releases/windows/2.0.1/VC-Composer-Setup.exe?token=…",
  "version": "2.0.1",
  "sha256": "e3b0c442…",
  "minimumOsVersion": "10.0.17763",
  "expiresInSeconds": 900
}
```

Fetch `url` before `expiresInSeconds` elapses (default 900, set by
`RELEASE_DOWNLOAD_TTL_SECONDS`), and verify the file against `sha256` when it is
not empty.

| Status | Body | When |
| --- | --- | --- |
| 400 | `{ "error": "Unknown channel. Use \"stable\" or \"preview\"." }` | any other `channel` |
| 401 | `{ "error": "Sign in to download VC Composer" }` (or "…the VC Composer preview") | not signed in |
| 403 | `{ "error": "Your account does not have a Windows 10 / 11 download. Subscribe, or try the free preview." }` | stable without a live licence for the platform |
| 404 | `{ "error": "Unknown platform" }` | `{platform}` is not `windows` or `macos` |
| 404 | `{ "error": "No published build for … yet" }` / `"No preview build for … is available right now"` | nothing live on that channel |
| 500 | `{ "error": "…" }` | database or storage error |
